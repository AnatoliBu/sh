## Design rules

- Keep `references/` mostly flat. It is a catalog of source-of-truth cards, not a deeply nested knowledge base.
- Keep domain folders organized by agent-harness concern: agent definitions, sources, skills, rules, workflows, evals.
- Do not mix source catalogs with executable agent behavior.
- Do not store secrets, credentials, private infrastructure dumps, customer data, or production configs.
- Treat blogs, snippets, Reddit, and LLM output as leads, not source of truth.

## From research to installed skill

The repository is both the workbench and the delivery channel. One direction only:

```text
research (research/, references/*.md cards)
  -> domain package (sysadmin-analytics-agent-kb/<domain>/: agent, skills, rules, workflows)
  -> installable plugin (plugins/<plugin>/) built by tools/build_plugin_from_domain.py
  -> marketplace entry (.claude-plugin/marketplace.json)
  -> installed on a machine: /plugin marketplace add AnatoliBu/sh + /plugin install <name>@sh-tools
```

Rules of the packaging step:

- **The domain is the source of truth; the plugin is derived.** Files under
  `plugins/*/skills/*/references/` carry a `<!-- generated by ... -->` marker and are
  rewritten on every build. Edit the domain, rebuild, never patch the copy.
- **Authored by hand:** `plugin.json`, `SKILL.md`, `agents/*.md`. The generator only checks
  they exist and that the skill name matches its directory.
- **Authority cards travel with the plugin.** Links `../references/<card>.md` are rewritten
  to `cards/<card>.md` and the cards are copied in, so an installed plugin resolves its own
  links with no access to this repository.
- **Nothing machine-specific or private goes into a plugin.** Local paths, employer
  internals, and personal stack notes stay out of the public package; keep them in a local
  or project-scoped skill next to the installed one.

```bash
python sysadmin-analytics-agent-kb/tools/build_plugin_from_domain.py                     # build
python sysadmin-analytics-agent-kb/tools/build_plugin_from_domain.py --plugin video-color # one
python sysadmin-analytics-agent-kb/tools/build_plugin_from_domain.py --check              # CI gate
python sysadmin-analytics-agent-kb/tools/validate_plugin_links.py                        # CI gate
```

Packaging config lives in `sysadmin-analytics-agent-kb/tools/plugin_packages.json`:
which domain feeds which plugin, how domain files map to `references/*.md`, and how cards
are selected (`auto` from domain links, `from-plugin-links` for packages whose references
are hand-written, or an explicit list).

## CI

The CI entry point is `.github/workflows/test.yml`.

It runs `sysadmin-analytics-agent-kb/tools/run_agent_kb_ci.py`, which validates:

- domain package structure;
- wiki links;
- frontmatter;
- agent artifact references;
- curated link graph;
- plugin packages in sync with their domains;
- plugin links, skill frontmatter, and marketplace registration;
- Quartz site build;
- markdown lint over the knowledge base **and** `plugins/`.

Quartz is cloned from `AnatoliBu/quartz`. If `QUARTZ_REPO_TOKEN` or `GITHUB_TOKEN` is available, CI uses token-based clone. If the Quartz repository is public and no token is available, the build script falls back to a plain public clone URL.
