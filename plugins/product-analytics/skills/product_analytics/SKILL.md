# Product / Data Analytics

Аналитика как решение, а не как выгрузка: сначала вопрос и решение, которое он поддерживает,
потом определения, и только потом запросы. Режим по умолчанию — **read-only**: смотреть
схемы, читать определения метрик, считать безопасные агрегаты. Публикация официальной цифры
или правка дашборда — через одобрение.

Источник методологии — домен `analytics` Agent KB (`AnatoliBu/sh`). Файлы в `references/`
сгенерированы из него; правки вносятся в домен, не в копию.

## Гейты, которые нельзя обойти

```text
definitions before queries   сначала определение метрики, потом SQL
no causal claims             «выросло из-за» требует дизайна, иначе это корреляция
grain discipline             одна строка = что именно; fanout ловится до выводов
time discipline              зона, границы окна, поздние события
publish gate                 официальная цифра — только после сверки и одобрения
```

## Формат вывода

Аналитический отчёт: вопрос → какое решение поддерживает → определения → источники данных →
метод → результат → ограничения. Число без определения и окна — не результат.
