# Rule: Skill Delivery

Правило про **доставку**: чтобы каждый скилл, дошедший до состояния «готов», ставился одной
командой и потом сам оставался актуальным. Про содержание скилла — другие правила.

## Reference links

Authority references:

- [Claude Code Plugin and Marketplace Format](../../references/claude-code-plugin-format.md)

## Направление потока — одностороннее

```text
research/            ресерч, черновики, сравнения
  -> references/     authority-карточки (плоско, по одной на источник)
  -> <domain>/       методология: agent.md, skills/, rules/, workflows/
  -> plugins/<name>/ УПАКОВКА, генерируется из домена
  -> marketplace.json
  -> машина пользователя: claude plugin marketplace add <repo> + claude plugin install
```

Обратного потока нет. Правка, внесённая в `plugins/**/references/*.md`, будет затёрта
следующей сборкой — и это не баг, а способ не иметь двух источников истины.

## Что генерируется, что пишется руками

| Файл | Кто владеет |
|---|---|
| `plugins/<name>/skills/<skill>/references/*.md` | генератор `tools/build_plugin_from_domain.py` |
| `plugins/<name>/skills/<skill>/references/cards/*.md` | генератор (копии карточек KB) |
| `plugins/<name>/skills/<skill>/SKILL.md` | автор |
| `plugins/<name>/.claude-plugin/plugin.json` | автор |
| `plugins/<name>/agents/*.md` | автор |
| `.claude-plugin/marketplace.json` | автор |
| `tools/plugin_packages.json` | автор |

Признак владения — маркер `<!-- generated by ... -->` в первой строке. Генератор трогает
только помеченные файлы: рукописный файл рядом с генерируемыми не перезаписывается, не
сверяется в `--check` и не удаляется как осиротевший. Смешивать в одном пакете авторские и
генерируемые references — допустимо и иногда нужно.

## Definition of done для нового скилла

Скилл считается доставленным, когда выполнено всё:

1. **Домен есть в KB** и проходит доменные валидаторы (структура, frontmatter, ссылки на
   плоские карточки).
2. **Пакет объявлен** в `tools/plugin_packages.json` — какой домен, какой скилл, какие файлы
   куда ложатся, как выбираются карточки.
3. **Сборка выполнена** (`build_plugin_from_domain.py`), `--check` проходит.
4. **`SKILL.md` написан как роутер**, не как учебник: назначение, таблица «что читать когда»,
   развилки, порядок. Лимит — держать в пределах ~120 строк; всё длинное уходит в
   `references/`, которые читаются по требованию.
5. **`description` во frontmatter триггерный**: не «Java QA skill», а перечисление задач и
   формулировок, при которых скилл нужен, включая формулировки на языке, на котором их
   реально пишут. Без него скилл не активируется сам, и вся упаковка бессмысленна.
6. **Плагин объявлен** в `.claude-plugin/marketplace.json` (`name` + `source`), и запись
   указывает на существующий каталог.
7. **Ссылки внутри пакета резолвятся** внутри самого пакета. Ссылка «в репозиторий» на
   машине пользователя мертва: карточки едут копией, пути переписываются на `cards/*.md`.
8. **Личного и рабочего в пакете нет.** Пути машины, имена внутренних систем работодателя,
   доменные имена стендов, замеры конкретного проекта — остаются в локальном или
   проектном скилле рядом с установленным. Публичный пакет содержит методологию.
9. **Гейты зелёные** — весь набор ниже, в CI, а не «у меня локально работало».

## Актуальность: не пиновать версию

Клиент пропускает обновление, если разрешённая версия совпадает с установленной, а
`version` в `plugin.json` **пинит** пакет.

```text
version в plugin.json  -> обновление только после ручного бампа строки
version отсутствует    -> версия = commit SHA -> обновление доезжает само
```

Правило по умолчанию для этого репозитория: **`version` в `plugin.json` не указывать.**
Пакеты живут на commit SHA, и пуш в `main` — это и есть релиз. `claude plugin validate`
предупредит об отсутствии версии — предупреждение принято осознанно и зафиксировано здесь.

Если для конкретного пакета версия всё-таки нужна (внешние потребители, зависимости с
semver-ограничениями), то вместе с ней принимается обязанность: **менять содержимое пакета
и не менять `version` — запрещено**, это ловится гейтом релиза. Одновременно в
`plugin.json` и в записи маркетплейса версию не держать: манифест побеждает молча.

## Порядок при изменении методологии

```text
правка в <domain>/**            (источник истины)
  -> build_plugin_from_domain.py
  -> прогнать гейты
  -> один коммит: домен + пересобранный пакет
  -> push (это релиз)
  -> на машинах: claude plugin marketplace update  [+ claude plugin update <name>]
```

Коммит, где домен изменён, а пакет не пересобран, — сломанный релиз: CI покажет дрейф.

## Гейты, которые это проверяют

| Проверка | Что ловит |
|---|---|
| `build_plugin_from_domain.py --check` | домен и пакет разъехались; лишний сгенерированный файл |
| `validate_plugin_packages.py` | битые ссылки и ссылки за пределы пакета, `SKILL.md`/frontmatter, `name` ≠ каталог, слабый `description`, раздутый `SKILL.md`, незарегистрированный плагин, домен без пакета, `version` без нужды |
| `validate_plugin_release.py --base <ref>` | содержимое пакета изменилось, а объявленная `version` осталась прежней |
| `validate_structure.py`, `validate_frontmatter.py`, `validate_agent_artifact_references.py` | домен как KB-артефакт |
| `markdownlint` по `sysadmin-analytics-agent-kb/**` и `plugins/**` | формат обеих сторон |
| `claude plugin validate <path>` (локально) | схема глазами самого клиента |

## Anti-patterns

- Правка в `plugins/**/references/*.md` вместо домена.
- Копирование файлов домена в пакет руками «на один раз».
- `version: "1.0.0"`, поставленная ради снятия warning'а, и больше никогда не поднятая.
- `description`, описывающий, что скилл «содержит», вместо того, когда его брать.
- `SKILL.md`, в который затащили весь домен: always-on-стоимость платится каждой сессией.
- Ссылка из пакета на путь этого репозитория или на абсолютный путь машины автора.
- Домен, который живёт в KB месяцами и никуда не упакован: «готово» без доставки.
