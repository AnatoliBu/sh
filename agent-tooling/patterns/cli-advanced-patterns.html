Advanced Agentic CLI Patterns

Source: Codex (gpt-5.5, xhigh) review session 2026-05-15. Validated against existing agentic_cli contract.

1. Structured —dry-run (before/after contract)

Core skill says “print what would happen”. Production contract: return the exact mutation shape.

Agent verifies mutation BEFORE executing. would_change: false = idempotent no-op.

2. Confirm-token for destructive ops

Prevents agent from hallucinating --yes. Two-phase commit:

Rules:

  • Token is single-use, short-lived (~5 min)
  • Token encodes operation + target + params hash — can’t be reused for different mutation
  • Missing/invalid token → exit 8 (unsafe operation refused)
  • Apply to: delete, bulk-update, permission changes, anything with side_effect: "destructive"

3. Rate limit handling

Envelope fields when rate-limited (exit 6):

  • retry_after_ms — agent sleeps exactly this long, no guessing
  • retry_budget_exhausted — true when repeated retries won’t help (quota, not burst)
  • Same pattern for upstream timeouts: "code": "upstream_timeout", "retryable": true

4. Pagination contract

Every list command:

Rules:

  • Default limit bounded (50-100), never unbounded
  • --all flag for full dump, but routes to --output file.json when > threshold
  • truncated: true — agent knows there’s more without comparing counts
  • total_known — nullable, only if backend provides it cheaply
  • Cursor is opaque string, not page number

9. Secret leakage prevention

  • Redact tokens/passwords in JSON output, stderr, and dry-run previews
  • auth_token: "sk-...abc" → "sk-...***" (show prefix for identification, mask rest)
  • Dry-run before/after must not include credential fields
  • --output file for large dumps — file may contain secrets, print path only to stdout

10. Eventual consistency

Write success ≠ immediate read availability:

Agent knows to wait or poll before verifying. Without this, agent reads immediately after write, sees stale state, concludes write failed, retries → duplicate.

11. Secret-injection wrapper (the secret-placeholder pattern)

§9 covers redacting secrets in a tool’s OWN output. This is the complementary pattern: a separate wrapper that feeds secrets from a vault into ANY child command so they never sit in argv/history/LLM transcripts. Reference impls: ~/.claude/bin/secret-env-wrapper (injector) + its a local safety wrapper around the vault CLI.

Two injection modes — support both:

  • env-mode: wrapper VAR=Entry [VAR:field=Entry …] -- cmd → resolve Entry from the vault, export as $VAR, child reads from env. Default field = the one holding the secret (e.g. the entry’s password field — document this; it bit us when we passed username: and got empty).
  • argv-placeholder mode: wrapper -- cmd --flag '{{vault:Entry}}' → resolve {{…}} tokens inside the child’s argv just before exec. For CLIs that ONLY accept a secret as an argument.

Rules:

  1. Prefer env/stdin over argv. Argv is world-readable (/proc, ps, shell history). Placeholder-in-argv still briefly exposes the secret in the child’s own argv — document that.
  2. Mask output. Capture child stdout+stderr, replace resolved secret VALUES with their {{…}} token before emitting, so secrets don’t leak into logs/transcripts. Caveat: when two entries resolve to the same value, masking collapses both to the first-registered token — a cosmetic ambiguity; disambiguate by other fields (host/db/port), not the masked token. Opt-out only via explicit NO_MASKING=1 (binary output / dummy secrets).
  3. Self-masking guard. Never resolve placeholders when the wrapped command IS the wrapper itself (basename(cmd[0]) check) — prevents an echo/recursion leak.
  4. Fail-fast on empty. If a lookup returns empty, exit non-zero naming the placeholder (never the value); don’t silently pass an empty secret.

For the underlying vault-CLI wrapper (the thing the injector calls): 5. Agent-safety blocking. Block subcommands that PRINT secrets (show --password, export, ls --format) or WRITE the vault (add/edit/rm/import), and unknown/alias subcommands (aliases can wrap secret-printers), unless an explicit ALLOW_SECRET_OUTPUT=1/ALLOW_WRITE=1 env opts in for intentional manual use. 6. Accurate diagnostics, not the upstream’s. When the vault can’t decrypt, don’t surface the third-party tool’s misleading message. E.g. with the agent daemon disabled, upstream prints “session expired / run login”, but the real cause is a missing/mis-resolved local key dir → preflight the local vault files and emit the true cause + fix. (Preflight the local vault state in the wrapper, e.g. an _assert_local_vault step.)

Where it lives: a bare-name entrypoint on PATH — see ~/.claude/bin/README.md for the “versioned CLI entrypoints on PATH” convention (dedicated bin/, NOT the mixed scripts/ dir).

Exit code matrix (expanded)

Codex-recommended expansion of the 0/2/3 baseline:

0  success (including idempotent no-op)
1  unexpected/internal error
2  usage/config/validation error
3  auth/permission error
4  not found
5  conflict / if-match mismatch (retryable: refetch + retry)
6  retryable external failure (rate limit, timeout, upstream down)
7  partial success (batch: some items failed)
8  unsafe operation refused / confirmation required

Tradeoff vs current 0/2/3+domain: more codes = more precise shell branching, but agents can reliably handle ~8 categories. Beyond that → structured error JSON.

Adoption: apply expanded matrix to born-agentic CLIs. For retrofits, extend incrementally — add codes 5-8 only when the command actually has those failure modes.
